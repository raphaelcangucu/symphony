## Root causes found and fixed

### 1. Symphony bug: run-spec `cwd` doubled into `<workspace>/backend/backend` (FIXED, uncommitted)

The preview runner resolves the run-spec `cwd` relative to
`SYMPHONY_WORKSPACE`, falling back to its launch directory. The Manager
launches the runner *inside the step's `working_dir`* and never passed the
workspace root, so a workspace-relative `cwd: backend` resolved to
`backend/backend` → `preview runner error: run spec cwd does not exist`.

Fix (left **uncommitted** in `/home/raphaelcangucu/symphony` for review):
- `elixir/lib/symphony_elixir/dev_server/manager.ex`: `serve_launch/3` now
  injects `SYMPHONY_WORKSPACE=<workspace root>` into the runner env (threaded
  `workspace_path` through `manual_server_plan/3` and `managed_launch_step/4`).
- `elixir/priv/preview/run.sh`: a spec *without* `cwd` now keeps running in
  the launch directory (legacy behavior preserved).
- `elixir/test/symphony_elixir/dev_server/preview_runner_manager_test.exs`:
  asserts the launch command carries `SYMPHONY_WORKSPACE` for a
  workspace-relative `cwd`. Focused run: `mix test test/symphony_elixir/dev_server/preview_runner_manager_test.exs`
  → 2 tests, 0 failures.

Daemon reload method: recompiled (`mix compile`) and hot-loaded the Manager
module into the running daemon via distributed Erlang
(`Node.connect(:"symphony@127.0.0.1")` + `:code.load_file/1`) — no daemon
restart, no running agents were disturbed.

### 3. Frontend dev SSR broken repo-wide: apollo config not serializable

Every SSR request failed with the masking error `IPC connection closed`
(vite-node). `nuxi build` surfaced the real error: the generated
`.nuxt/apollo.mjs` contained `function () { [native code] }` — the
`@gambalabs/apollo` module's default `retryOptions.attempts.retryIf` function
serializes as native code, producing invalid JS. Worked around by patching
`node_modules/@gambalabs/apollo/dist/module.mjs` (serializer emits a safe
`((error) => !!error)` for native-code functions) in both worktrees, and
adding `routeRules { '/task1'|'/task2': { ssr: false } }` so the task pages
render client-side. The same defect breaks `@nuxt/test-utils` project mode
(`DataCloneError` on structuredClone of the config) — upstream fix needed in
the `@gambalabs/apollo` package.

### 4. Backend serve stub + broken saved step

The saved dev-env backend step launched `.symphony/serve.sh`, a deliberate
fail-fast stub → `supervised process exited with status 1`. Replaced with the
real serve flow (now `preview-backend.sh`). Also `storage/logs` was missing in
the fresh shallow clones (supervisord's reverb program refused to start);
created the Laravel storage skeleton in both worktrees.

### 5. Single-threaded `artisan serve` starvation (incl. Xdebug)

The app container runs PHP's built-in server. With `SAIL_XDEBUG_MODE=develop,debug`
every request spent ~500ms trying to reach an Xdebug client; the 1s-interval
health probes saturated the single worker and all other requests (including
`/health` from the frontends) timed out indefinitely. Fixed by
`SAIL_XDEBUG_MODE=off` in both backend `.env` files and
`PHP_CLI_SERVER_WORKERS=8` in `docker-compose.vibe.yml`.

### 6. Misc

- Stale zombie `betting-app` published port 4107 and hung all connections,

- `docker exec` as root left a root-owned `config/psysh` dir that made Laravel
  return 500 on every request (config loader permission error); removed, and
  subsequent execs run as `sail`.
- The task pages' health endpoint (`/api/symphony-preview-check`) had no fetch
  timeout; probes of a black-holed port hung SSR forever. Added
  `retry: 0, timeout: 15000` in both worktrees, plus the GoAPI `Origin` header
  in GAM-21 (GoAPI rejects empty-origin requests; GAM-22's agent already did
  this) and updated GAM-21's unit test accordingly.
- Frontend `.env.local` wiring (`GRAPHQL_BASE_URL`, `GRAPHQL_INHOUSE_URL`) and
